# Netflix UX Design - From Browsing to Belonging

**An independent UX mentorship concept exploring faster content discovery for limited-time viewers.** The core idea, **Tonight, quickly**, lets a viewer optionally narrow fictional recommendations by time, audio language, and mood, then compare the signals that matter before choosing Play or saving a title.

## Files

- [Case study PDF](Netflix_UX_Case_Study.pdf) - end-to-end project narrative: research framing, competitor scan, proto-persona, JTBD, journey, IA, user flows, three wireframes, visual direction, concept screens, and validation plan.
- [Clickable prototype](index.html) - self-contained responsive experience; open locally in a browser or publish with GitHub Pages.
- [Research and validation kit](Netflix_Research_and_Validation_Kit.md) - interview plan, neutral questions, test tasks, measures, blank session records, and sources.

## Evidence and scope

This is an independent concept and is not affiliated with Netflix. It does not use a live Netflix catalog or stream video. Titles and availability in the prototype are fictional.

The case study does not invent interviews, participant quotes, usability results, or outcome metrics. The persona is a scenario-based proto-persona; research hypotheses and the AI-assisted self-review are labeled. Three viewer interviews and three participant test sessions are planned, not reported as completed.

1. Sign in to GitHub and choose **New repository**.
2. Enter the repository name above. Add the description above.
3. Choose **Public** if the manager should be able to review it without access. Keep it private if your organization requires that.
4. Leave **Add a README file**, **Add .gitignore**, and **Choose a license** unchecked. The finished README is one of the four files you will upload.
5. Create the repository.
6. On the empty repository page, choose **Add file**, then **Upload files**. Drag in the four files listed above.
7. In the commit message field, enter: **Add Netflix content discovery UX case study**.
8. For a new repository, commit the upload to its default branch. If GitHub instead asks you to propose a change because the branch is protected, create the branch and follow GitHub's prompt to open the pull request.
9. Commit or propose the changes, then open the repository page and confirm all four files appear. Open the PDF and click index.html to confirm both are visible to your reviewer.

GitHub's current browser upload flow supports multiple files and commits them through the upload page. See [GitHub Docs: Adding a file to a repository](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository).
